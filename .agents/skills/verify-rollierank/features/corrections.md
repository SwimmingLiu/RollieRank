# 答案反馈、审核与重算

验证用户从入口完成操作后的真实结果，并核对持久化的业务状态。

## Sub-features

逐题纠错、多题依据、取消、保存锁和重试、待审试算；维护者凭证、审核、驳回、订正通知、分数变化、受影响答卷与未来标准。

## How to get to it (user POV)

手机逐题对照右上角纠错，练习记录的维护者审核，成绩卡内真实订正状态；基础报告反馈和套卷管理审核。

## Driving it with verification CLI

Preconditions: 已按主Skill安装依赖；CLI启动隔离服务并通过doctor；不复用4781的日常数据。

运行 `npm run verify -- feature corrections`。提交多题反馈并试算，确认正式成绩未变；错误凭证拒绝、正确凭证审批后，原报告、分析与榜单同步，选项和原提交时间保持不变。

证据保存在输出目录的日志、浏览器截图、ARIA快照和结果JSON中。命令非零退出即为未通过，不能把缺少依赖记成成功。

## Gotchas

审核凭证仅在临时服务配置；取消、遮罩和Escape不发送反馈；旧版「示例估分」仅为静态身份，不表示答案有误。

手机从逐题对照的「待检查」或题号进入实际题目的反馈，按「我的／参考」核对后以 A–D 单选与依据提交。全局入口先选题，单个存疑题可直接带入。支持增加其他明确题号，选择器不默认生成题目 1；题型标题及「全部板块」可切换复盘板块。`test/ios-question-feedback-browser.test.js` 以真实粉笔卷验证标记跨提交、两题 payload、板块跳转与分布→原题反馈；缩放 iframe 还必须操作真实单选命中区。

原生小程序从逐题对照标题栏的「反馈」进入。打开「反馈记录」可查看当前答卷的处理进度、试算和维护者审核。审核后，在成绩卡核对「答案已订正」、前后分数和理由。用有待审或已处理反馈的账号检查「练习记录」，岗位和成长分析下方应紧接练习筛选。

独立运营后台登录后可进入 `/admin/#corrections` 接单并审核。浏览器专项的手机和基础流程分别通过各自的入口核对试算与重算。

单题和多题反馈都须在 320×568 首屏完整显示同一行取消／提交；字段单独滚动。缩至 320×330 时，聚焦依据输入保持在提交行上方，按钮仍在视口内。实际控件存在数量也须校验，不能因查询到零个按钮而误判对齐。
