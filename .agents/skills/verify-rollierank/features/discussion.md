# 本卷交流与多媒体评论

验证用户从入口完成操作后的真实结果，并核对持久化的业务状态。

## Sub-features

真实数量、试卷范围、头像与默认昵称、文字照片、正文自动链接、点赞与取消、回复评论和回复他人回复、展开与收起；输入自增高和全屏编辑、草稿、失败重试幂等、根评论及回复分页。

## How to get to it (user POV)

手机真实报告固定底栏的评论图标进入「全部评论」。底部发言栏旁常驻照片图标，可直接选图；回复时显示目标内容片段。基础入口为正式报告的试卷讨论。

## Driving it with verification CLI

Preconditions: 已按主Skill安装依赖；CLI启动隔离服务并通过doctor；不复用4781的日常数据。

运行 `npm run verify -- feature discussion`。从真实报告进入交流页，输入正文 URL 与照片，验证增高、全屏、关闭重开草稿和真实发送。使用 A、B、C 三个独立真实练习身份，让 B 点赞 A、C 回复 A、B 回复 C，核对目标昵称、数量、重载、展开收起与分页。模拟写入失败和响应丢失，重试后只产生一条评论或回复；并发重复点赞只增加一次。检查跨卷凭证拒绝和接口返回的身份字段。

证据保存在输出目录的日志、浏览器截图、ARIA快照和结果JSON中。命令非零退出即为未通过，不能把缺少依赖记成成功。

## Gotchas

编辑器使用已有昵称，无资料时为「卷友」。示例只提供「去练习」，不能调用正式讨论。总数包含评论与回复，根评论分页与回复分页独立；喜欢状态仅向当前身份返回 likedByMe。手机端暂缓语音，专项必须确认没有麦克风调用、录音控件或音频播放器；后端继续兼容已保存的媒体。

专项为 `test/discussions-interactions.test.js`、`test/discussions-moderation.test.js`、`test/ios-discussions-interactions-browser.test.js` 与原评论回归。原尺寸证据覆盖 320／390／430，输入、发送和图片按钮须对齐，长回复不得越出纸卡。评论审核管理位于桌面端运营后台（`#/admin`），支持微信小程序内容安全（文本 `msgSecCheck`、图片/语音含图中文字 `mediaCheckAsync` 及 `/api/wechat/sec-callback` 异步回调）、自定义敏感词、先审后发切换、评论通过/屏蔽/删除与配图核查。

主评论、回复及回复他人的草稿须在真实整页刷新后恢复文字和照片，相同内容重试沿用幂等标识。检查存储被拒绝后的恢复提示，320×568 长目标内容的发送／取消边界，以及缩小视口后的照片移除和发送可达。缩小视口只是布局验证，不代表已测试实体系统软键盘。

原生评论区不单独占一行重复展示评论图标和总数。主评论使用头像、作者、正文、时间和操作；回复缩进到所属主评论下，并可同时展开多个线程。每线程独立维护回复分页，回复目标保留被回复者昵称。评论输入栏常驻照片和发送动作，不显示重复的用户头像占位。
