# 视觉渲染与 UI 设计合理性审查

本功能守卫 RollieRank（手机网页 `/ios-v3/` 与微信小程序 `mini-program/`）的两道质量门禁：**视觉渲染无硬伤**与**页面 UI 设计合理性**。自动化脚本拦截可量化的渲染/契约退化，原尺寸截图人工/视觉复查拦截「代码跑通、断言全绿，但页面从设计上就不合理」的结构性问题。

## Sub-features

1. **视觉与渲染硬伤门禁（Visual Rendering Gate）**
   - **原生层不穿层**：小程序 `<canvas type="2d">` 图表（报告页六维雷达 `rr-radar`、成长分析走势图 `pages/analytics`）必须采用离屏绘制转 `<image>` 展示，绝不覆盖 `sticky` 顶栏、`fixed` 底栏或打开中的底部抽屉。
   - **微信 `<button>` 样式防崩坏**：显式覆盖小程序按钮默认的 `184px` 宽度、`margin: auto` 与 `::after` 边框，防止分段标签溢出底槽（选岗省考 Tab）、横排芯片塌成居中长条（成长分析来源）、右对齐图标悬空（交流页点赞）、伪元素标记被吞（答题卡存疑圆点）。
   - **控件对齐与窄屏可读**：同行时间/回复/点赞垂直居中对齐；表单按钮文字垂直居中；日期框具可见边框；320px 窄屏三位数题号（`100`–`135`）不折行裁切；分页箭头朝向与左右语义一致；单题模式 2×2 选项字母居中且右上角状态圆标在未选/选中态形状统一、卡内无多余底部空腹。
   - **视口密度与卡片比例**：套卷目录按常见 6–12 套校准双行卷卡尺寸，12 套在主流手机一屏内排布均衡，既不单行挤撞也不留大块底部空白。
   - **预览与导出所见即所得**：成绩分享 4 模式预览（长图/成绩卡/题型/雷达）与真实导出的 900px PNG 内容、对齐（百分比右对齐进度条、同卷排名右对齐）、水印图文、做题用时一致，卡片底部无多余空壳留白。

2. **UI 设计合理性门禁（UI Design Rationality Gate）**
   - **信息归属清晰**：详情页、报告页、复盘页必须让用户一眼辨识当前套卷身份（不丢卷名）；空态文案必须匹配当前筛选条件（例如岗位空榜不得写「这份卷还没有人参与」）；同卷多次练习的报告页必须展示「上次 VS 本次」对比卡与板块变化。
   - **数值严谨无原始浮点噪音**：所有内置卷按国考 130 题（地市）/ 135 题（副省）等满 100 分整数分值精确计分，不得出现 `99.5 → 100` 除不尽折算，界面分值一律经格式化展示、不得出现 3 位及以上浮点长尾巴（如 `4.020100502512563`）。
   - **零冗余文案与命名统一**：页内卡片不得反复复述页标题或机构名（如「上岸村套卷」卷卡去掉 `上岸村 · `，系列标题去掉重复 `公考`）；全站不得泄露内部机构代号（统一显示「花生」而非「四海」）；同级机构套卷卡片格式保持统一。
   - **控件表意与主次一致**：易歧义功能不得只放孤立图标（复盘底部主按钮带「复制错题号」文字、同卷榜范围栏带「本岗/全国/查岗」短词、审核页清晰区分「刷新 / 解锁审核 / 退出审核」）；连续确认弹层的主/次按钮左右位置与关闭入口保持一致；顶部大数字必须带指标口径标签（如「最近得分率」），装饰图标不得误像 Loading 圈。
   - **交互闭环与参数保真**：跨页带参跳转必须真实落地（如报告页点具体板块卡进入复盘必须按该板块筛选，不可静默退回全部）；输入/点赞/回复具备清晰视觉反馈（发送按钮区分空态与可发送高对比态、已赞心形实心变色、点回复自动聚焦）。

## How to get to it (user POV)

- **小程序端**：从 `pages/home` 依次走通「花生期数选择 → 上岸村套卷 → 录答案（列表/单题/板块/答题卡/交卷确认/选岗提醒）→ 成绩报告（含订正后雷达与底栏边界）→ 点具体板块进复盘 → 反馈与审核 → 同卷榜（本岗/全国/查岗 + 选岗省考空态与四级详情）→ 本卷交流（点赞与楼中楼回复）→ 成绩分享 4 模式与导出 PNG → 练习记录 → 成长分析与筛选抽屉 → 个人资料与修改昵称」。
- **手机网页端**：访问 `/ios-v3/` 全部视图在 320 / 390 / 430 / 1440 宽度的渲染截图与交互轨迹。

## Driving it with verification CLI

1. **自动化契约与视觉防线（本地与 CI 必跑）**：
   ```bash
   npm run verify -- feature visual-design-audit
   ```
   执行 `test/miniprogram-design-rationality.test.js`、`test/miniprogram-layout.test.js` 与 `mini-program/tools/check.mjs`，验证防穿层、按钮样式、去冗余命名、跨页解码、海报对齐与配置完整性。

2. **微信开发者工具实拍与几何审查（改动小程序 UI 必跑）**：
   按[小程序测试环境](../../../../mini-program/README.md#测试环境)生成隔离构建，启动 `cli auto` 后运行：
   ```bash
   MINIPROGRAM_FLOW_OUTPUT=<项目外输出目录> \
   MINIPROGRAM_AUTOMATION_PORT=<端口> \
   MINIPROGRAM_API_BASE=http://127.0.0.1:<服务端口> \
   MINIPROGRAM_REVIEW_TOKEN=<测试凭证> \
     node mini-program/tools/flow.mjs
   ```
   除检查 `result.json` 零失败外，**必须人工或视觉逐张打开原尺寸截图与导出的 `poster-*.png`**，逐项对照上方「视觉渲染硬伤」与「UI 设计合理性」清单，确认无穿层、无溢框、无错位、无冗余复述、无语义歧义。

3. **完整门禁（发版或交付前必跑）**：
   ```bash
   npm run verify -- all
   ```
   同时检查 `/ios-v3/` 在 `test-results/verification/visual/` 的 320 / 390 / 430 / desktop 原始分辨率截图。

## Gotchas

- **自动化全绿不等于设计合理**：例如原 `flow.mjs` 仅断言跳转路径为 `pages/review/review` 时，漏检了未解码 `query.type` 导致板块筛选回退全部的问题；雷达 `<canvas>` 穿层、按钮文字贴顶、发送图标近白隐形也无法仅靠逻辑断言发现——**必须看原图**。
- **区分有意极简与真实缺陷**：选岗抽屉无标题栏与左滑返回、计时路径纯图标返回、设置页仅留昵称、练习记录不挂反馈卡是已确认的产品契约，审查时保留这些特色，不与真实可用性缺陷混淆。
- **微信开发工具测试目录隔离**：切勿用指向历史测试临时目录（含合成第 3–10 期数据）的旧构建判断真实套卷目录；验证真实目录分级须连接干净隔离数据目录。
