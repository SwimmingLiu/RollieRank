# 成绩分享与导出

验证用户从入口完成操作后的真实结果，并核对持久化的业务状态。

## Sub-features

手机整份报告、成绩卡、题型和雷达四样式、自动适配与真实 PNG 下载；三种基础海报、昵称日期设置；完整逐题CSV、错题号复制、同卷链接、原始满分。

## How to get to it (user POV)

手机报告底部分享按钮与分享页；基础报告的留下成绩、导出CSV，逐题对照的复制和导出。

## Driving it with verification CLI

Preconditions: 已按主Skill安装依赖；CLI启动隔离服务并通过doctor；不复用4781的日常数据。

运行 `npm run verify -- feature sharing`。手机由真实交卷报告进入分享，切换四个样式并在不同画板自动适配，通过底栏保存每种 PNG，核对尺寸、真实正误空和长图完整内容。预览下边缘不得越过保存栏。用真实报告生成PNG并检查文件头和尺寸，基础入口切换三种样式并分别导出；下载CSV核对题数、两位分值及原选项。

证据保存在输出目录的日志、浏览器截图、ARIA快照和结果JSON中。命令非零退出即为未通过，不能把缺少依赖记成成功。

## Gotchas

海报由实际组件导出；不同题量或非100分套卷必须保持实际满分；复制的本机链接不能代表公网部署。

四模式身份含真实年份与系列／卷类，品牌置于底部水印。真实页不再有独立品牌／年份头与估分小标题。当前画廊动效由 `node scripts/record-ios-preview.mjs` 录制，之后运行 UI 的 `preview:assets` 更新引用；预览回归核对实际 GIF 与构建、指定 Logo 的哈希。

导出密度按实际 PNG 尺寸与海报 CSS 尺寸计算，雷达 backing canvas 至少覆盖此比例；高设备 DPR 继续保留。真实底栏下载过程中的 canvas 测量与 PNG 必须一致，不能只看预览截图。

原生分享页在 450px 原稿画板上直接渲染纸卡，再按容器宽度等比缩放，不能把整张 Canvas 导出图缩回页面作预览。长图、成绩卡、题型和雷达分别核对身份、分数、结果数、名次和水印。雷达在未缩放的离屏画布上生成，再作为普通图片放回纸卡，避免微信原生 Canvas 不跟随祖先缩放。雷达图只在长图与雷达模式出现，板块列表只在长图与题型模式出现。保存按钮仍生成整张 PNG，点击相册保存时再请求微信权限。
