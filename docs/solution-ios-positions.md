# iOS 选岗与排行接入方案

组合现有 `createPositionsFeature`，只增加返回副本的 `snapshot()`，复用原有搜索分页、选岗提醒、参与、撤回、文件导入和服务端接口。iOS 包装提供原生排名组件宿主，并将 `rows/self/count` 映射为 `RankingProps`。React 组件保留成熟 Tabs、Card、Avatar、NumberTicker 和 TiltCard，动态题型从当前真实版本构造。

并列名次保留 API 值，前三张卡按可见顺序放置，使用独立的领奖台槽位区分视觉位置与实际名次，避免两个第一名产生重复 React key。未参与使用 null，空榜与加载失败不填样例人物或固定排名。全国、个人岗位、其他岗位和参与入口使用原模块的专用委托事件。

`standing()` 独立读取当前真实版本的总分榜，默认采用个人所选岗位，未选岗时由服务返回全国。报告和分享路由均加载，不跟随浏览其他岗位的临时筛选，也不从旧样例报告生成名次。不同版本和过期请求分别处理。

新增 CSS 只作用于 iOS 功能区域与岗位弹层，复用原岗位局部样式并映射到现有白、深灰、浅珊瑚色。专项测试使用独立端口、实际服务和临时成绩，直接构建最新 ranking.tsx 到临时目录，不修改共享 vendor。最终 4781 端口及组合入口由协调对话验收。
