## 0. 一句话理解这个产品

**一个"纸质刷题 + 手机记分"的工具，外加一堆流量工具。**

用户在线下做纸质套卷，做完把答案录进小程序（手点或拍答题卡），系统估分、给排名、给逐题选项分布。在此之上挂了一组**与记分无关的引流工具**：备考计时器、百化分速算训练、成语例句检索、粉笔排版工具。

主流程只有一条：

```
首页 → 选套卷 → 选录入方式（手动/扫描）→ 答题卡 → 交卷 → 成绩报告
```

其余 12 个页面都是**旁支**，分布在三个不同层级的入口里。

## 1. 全局设定

### 1.1 视觉

| 项 | 值 | 用在哪 |
|---|---|---|
| 主色 | `#2C3E50` 深蓝灰 | 导航栏、选中态、主按钮、标题 |
| 强调色 | 暖黄 `#F5D08A` 系 | 答题 CTA、得分卡、NEW 徽标 |
| 错误色 | `#E74C3C` 红 | 错误数、删除、脱离主色的工具页 |
| 成功色 | `#4CAF50` 绿 | 正确数、交卷确认 |
| 页面底色 | `#F5F7FA` | 全局 |
| 卡片 | 白底 + 1.5px 描边 + 圆角 16px | **全站统一的容器语言，不用阴影** |
| 字体 | 系统无衬线 | 标题 32–56px，正文 28px，说明 24px |

**关键：描边卡片体系。** 全站没有一处用 box-shadow 做层次，全靠"白底 + 深灰描边 + 圆角"形成实体卡片感。这个选择让界面在低端安卓机上也不会糊，代价是观感偏"文档化"。

### 1.2 导航模型（这是混乱的根源之一）

小程序**没有 tabBar**。所有页面都靠 `navigateTo` 层层深入，靠左上角 `‹` 返回。

- 顶部导航栏：`navigationStyle: custom`，标题居中
- 首页右上角有"更多"入口（`onGlobalClick` 收起点按区域）
- 底部：无底栏

后果：**用户在 18 个页面里只能靠"返回"这一条路径回溯，没有全局导航**。从"备考计时器"想回"我的练习记录"，必须连按 3 次返回。

### 1.3 数据与账号

| 项 | 实现 |
|---|---|
| 账号 | 微信 openid（`cloudfunctions/login`） |
| 数据 | 微信云开发（`exam_rank_stats`、`exam_data` 等集合） |
| 本地 | `wx.setStorageSync` 存草稿、缓存、每日弹层标记 |
| 题目来源 | 三套题库：`peanut`（花生十三）、`chaoge`（超格）、`fenbi`（粉笔） |
| 缓存 TTL | 成语搜索 1 小时（`36e5`），其他 10 分钟 / 1 天不等 |

### 1.4 变现

| 广告位 | 触发条件 | 强度 |
|---|---|---|
| 扫描交卷广告 | `scanAdStage` — **必须看完广告才能交卷**，答案保留 | 强 |
| 计时器保存预设广告 | `initRewardedVideoAd`（`adunit-73025744ccf291a4`） | 中 |

## 2. 页面地图

18 个页面 + 1 个组件。按**功能域**归类（不是按源码顺序）：

```
首页 pages/index/index
│
├─【主流程】套卷 → 答题 → 成绩
│   ├─ pages/exam/exam            答题页（手动 / 扫描双模式）
│   ├─ pages/result/result        成绩报告（v78：能力图 / 英雄榜 双面板）
│   ├─ pages/set-history/          历史与榜单
│   └─ components/hero-ranking/   英雄榜组件（复用于成绩页/历史页）
│
├─【变现】[v78 新增]
│   └─ pages/support/support      赞赏开发者（iOS 内购 / 安卓微信支付）
│
├─【工具】首页"常用工具"区 4 个入口
│   ├─ pages/timer-setup/          备考计时器 → timer → timer-report
│   ├─ pages/timer-records/        本地计时记录
│   ├─ pages/math-tools/menu/      数学计算 → percentage → percentage-result
│   ├─ pages/idiom/                官媒搜索 → idiom-reader
│   └─ pages/fb-tool/              粉笔排版工具（纯外链引导）
│
├─【内容】
│   └─ pages/letter/letter         开发者的一封信
│
└─【隐藏入口】首页长按标题输密码 "admin"
    ├─ pages/user-list/            所有用户
    └─ pages/admin/report-list/    错误反馈列表
```

**关键观察：三层入口混合。** 主流程在首页首屏，工具在首页下方滚动区，管理页藏在长按密码后。用户没有任何视觉线索知道"下面还有东西"或"长按有东西"。

**v78 的结构变化**：首页标题栏右侧多了一个常驻的「💰 打赏开发者」按钮（此前这里是个被 feature flag 恒关的客服按钮，用户看不到）。它把**变现入口放在了一级视觉动线**上，是本次更新唯一改变首屏信息密度的改动。

## 3. 逐页功能与交互

### 3.1 首页 `pages/index/index`

**作用**：套卷目录 + 工具入口 + 三个彩蛋。

#### 结构（从上到下）

1. 大标题「**模拟卷刷题**」+ 每日一词日期
2. **打赏按钮** `[v78 新增]`：标题行右侧「💰 打赏开发者」 → `pages/support/support`
3. **信件入口**：圆形信封图标 + 「致考公小伙伴们的一封信 —— from独立开发者」
4. **题库切换胶囊**：`🥜题库` + 右侧双段控件 `超格 | 粉笔`
5. **套题卡片列表**：
   - 每张卡 = 左上 `展开` 小标签 + `NEW` 黄标 + 花生 emoji + 标题 + 右侧圆形箭头
   - 展开后列出该期的各套（二期-第1套 / 共130题 / `历史` + `答题` 两个按钮）
6. `加载更多套题` 描边按钮
6. **常用工具**分组（左侧圆点标题）：
   - FB排版工具获取 / 官媒搜索 / 备考计时器 / 数学计算
   - 每项 = 标题 + 副标题说明 + 圆形箭头
7. （滚动到底）底部信息

#### 交互细节

| 交互 | 实现 | 备注 |
|---|---|---|
| 切换题库 | `onSwitchLibrary` → 重置 `categoryLimit=3`、清空 `activeCategory/periods/expandedExams` | 切换即重置，用户之前的展开状态丢失 |
| 展开套题 | `onToggleExamExpand` → 单开模式（`expandedExams` 只保留一个 key） | **同时只能展开一个**，点新的会收起旧的 |
| 点任意区域 | `onGlobalClick` → 收起所有已展开的套题 | 误触风险高，点列表空白处也会收起 |
| 懒加载分类 | `categoryLimit` 初始 3，`onLoadMoreCategories` 每次 +N | 首屏只显示 3 个分类 |
| 下拉刷新 | `onPullDownRefresh` → `refreshCatalog` | |
| 预加载 | `preloadFirstExamLeaderboard` — 进首页就预取第一个套卷的榜单 | 性能优化 |

#### 三个彩蛋（产品设计上最值得注意的部分）

**① 转盘预测分数**（`onPredictScoreTap`）

转盘不是图片，是 **canvas 现场绘制**（`drawScoreWheel`）：

| 项 | 值 |
|---|---|
| 刻度（12 段） | `[160, 152, 148, 141, 136, 129, 123, 118, 112, 106, 99, 92]` |
| 配色（4 色循环） | `#2C3E50` `#55E6C1` `#FAD390` `#A2D2FF` |
| 圆心 | 固定写 `160`，白底 + 深色描边 |
| 尺寸 | `wheelSizePx`，默认 280 |

绘制完成后 `canvasToTempFilePath` 存成临时图片（`wheelImagePath`），避免每帧重绘。

```
点击 → 转盘旋转 360×(6~10 圈) + 随机偏移
    → 4.2 秒缓动动画
    → 双次强震动 vibrateDoubleStrong
    → 弹出"短信通知"横幅
```

**注意这是一个纯娱乐彩蛋**：指针落点由随机数决定，和用户任何真实成绩无关，但短信文案写得像真的一样（"你以160分（第一名）的成绩入围面试"）。产品上属于"情绪价值"，不承担任何指导功能。

短信横幅内容（写死的段子）：

```
【公务员平台】
同学你好，你以160分（第一名）的成绩入围面试，
请于3.25日前确认你是否参加面试。
```

8.7 秒后自动消失（`setTimeout(..., 8700)`）。

**② 每日励志弹层**（`maybeShowMotivationOverlay`）

- 用 `motivation_last_shown` 存日期，**每天只弹一次**
- 标题「致决战省考的你：」，正文是长段情感文案（"经济下行，考公难度一路飙升…"）
- 支持**语音播放**（`playMotivationAudio` / `onMotivationToggleAudioTap`），音频本地缓存（`ensureMotivationAudioLocalPath`）
- 悬浮按钮（FAB）可随时重新打开

**③ 隐藏管理入口**

- 长按作者名（`onAuthorLongPress`）→ 弹密码框
- 输入 `admin` → 显示"开发者后台"菜单（查看用户列表 / 错误反馈）
- 这是**唯一的后台入口**，普通用户完全不知道

### 3.2 答题页 `pages/exam/exam`

**作用**：录入答案。这是全产品最复杂的页面（19KB 逻辑）。

#### 双模式

| 模式 | 入口 | 说明 |
|---|---|---|
| `entryMode: "manual"` | 点「答题」→ 选「手动录入」 | 逐题点选 |
| `entryMode: "scan"` | 点「答题」→ 选「扫描识别」 | 摄像头扫专用答题卡 |

切模式通过 URL 参数：`/pages/exam/exam?examId=xxx&entry=scan`

#### 手动模式界面

- 顶部横向章节 tab：`逐题` 胶囊 + 政治理论 / 常识判断 / 言语理解 / 数量关系…
  - 当前 tab 深色填充，可横向滑动
- 章节标题 + 右上角 `共 20 题`
- 答题卡：每行 = 大号题号 + A/B/C/D 四个方形按钮
  - 未选：白底描边
  - **已选：整块深色反转 + 白色字母**
- 底部固定：`下一章` 描边 + `交卷 / Submit` 深色实心

#### 扫描模式（技术实现最重的一块）

依赖 7 个模块：

| 模块 | 职责 |
|---|---|
| `utils/scan-session.js` | 扫描会话状态机 |
| `utils/scan-guidance.js` | 引导文案与步骤 |
| `utils/live-scanner.js` | 实时摄像头 |
| `photo-frame.js` | 照片打包 |
| `photo-quality.js` | 照片质量判定（是否重拍） |
| `torch-preference.js` | 补光偏好记忆 |
| `scan-submit-ad.js` | 扫描交卷广告门 |

运行时状态：

```js
scanner: {
  phase: "idle",
  hint: "试卷加载完成后自动开启持续扫描",
  progress: 0,
  required: 2      // 需要拍 2 张
}
```

页面级细节：

- `markerPresence: [false,false,false,false]` — 实时检测四个定位块是否入镜
- `guideTitle: "对准四个定位块"` / `guideTip: "让纸卡四个黑色定位块分别靠近四个绿框，题区完整入镜。"`
- `gyro` — 陀螺仪辅助水平
- `torchEnabled` — 手电筒
- `captureMode: "photo"` — 支持拍照和连续扫描两种
- `workerReady` — 识别 worker 就绪状态
- `scanVersion: "照片／连续扫描 · 10.10-40"`

**隐私流程**：`agreeLivePrivacy` / `rejectLivePrivacy` / `openLivePrivacy` / `livePermissionsChanged` —— 首次使用要同意隐私协议才能开摄像头。

**答案卡下载**：`onDownloadAnswerCard` 下载 A4 专用答题卡 PDF。**这是扫描模式的前置条件** —— 没有它扫不了。

#### 提交

### 3.3 成绩页 `pages/result/result`

**作用**：整份报告。v78 起 39.6KB，**全站最重的一页**（v76 是 33.4KB）。

#### 结构（v78）

1. 顶部套卷名胶囊 + 右上 `保存图片`
2. **得分卡**（暖黄）：
   - 超大分数 `0.0` + `分`
   - 「超越 5.8% 对手」
   - 「参考排名」+「1002 / 1064」（v78 起拆成标题 + 数值两行）
3. 三栏统计：`0 正确`（绿）/ `3 错误`（红）/ `127 未做`（灰）
4. **洞察 Tab 条** `[v78 新增]`：`能力图` | `英雄榜`，**默认停在「能力图」**
5. **能力图面板** `[v78 新增]`：
   - 六维雷达：政治理论 / 常识判断 / 言语理解 / 数量关系 / 判断推理 / 资料分析
   - 分段按钮：`60 分段` / `70 分段` / `80 分段`（事业单位 A 类为 90/105/120）
   - 图例：`我的表现`（砖红）/ `<n> 分段平均`（蓝）/ `<n> 分段平均`（绿，更高分段）
   - 样本说明：`60 < 分数 ≤ 70 · 328 份答卷`，脚注「差值单位为百分点」
   - 空态：`正在读取分段统计…` / `该分段暂无可比统计` / `本卷暂无能力图`
6. **英雄榜面板**（`components/hero-ranking`，切到该 Tab 才加载）：
   - 🏆 标题 + 右侧 `登录：完善信息` 头像胶囊
   - 列表项：排名徽章（金银铜）+ 头像 + 昵称 + 时间 + 分数
   - 每项右侧柱状图小图标按钮 → 打开该用户详情
   - `查看前十名` 文字链接
7. **逐题选项分布**（`isAdvancedMode` 高级模式）：
   - 每行 = 题号 + 四个选项格
   - 每格 = `字母 + 百分比 + (人数)`
   - 正确答案绿底
   - 按章节分组，**可折叠**（`sectionCollapsed`）
8. **章节统计卡**：`常识判断` + 右侧胶囊 `0 / 15题 | 正确率: 0.0%`
9. 底部：`返回首页` + `发现错误`

#### 能力图的算法要点

**不是抽样估计**，而是对云端累计桶做差分：

```
filteredQuestionStats[band] 是「分数 > band」的累计统计
  → 两个累计桶相减 = 落在 (band, next] 区间的人
  → 得到该分段每个模块的实际正确率
门槛：总样本 ≥ 10 人、该分段 ≥ 10 人、最高分名次必须为 1，否则整段对比关闭
```

半径映射把「和同龄人比」放在图形的主要面积上：

```
低于分段平均  → 压缩在人群环以内
等于分段平均  → 落在人群环
高于分段平均  → 从人群环线性升到内环
超过下一分段  → 走饱和曲线冲向最外环
```

作废条件：任一题的标准答案不是单个 `A/B/C/D` → 整张雷达返回空，落到「本卷暂无能力图」。

#### 数据来源

```
loadQuestionStats() → 云函数/集合 exam_rank_stats
  → questionStats: { q_1: { acc: 49, count: 876, dist: {A:5,B:24,C:49,D:22}, distCount: {...} } }
  → filteredQuestionStats: 按分数段筛选后的同一结构
```

**分数筛选档位是动态算的**（v78 里拆成 `U()` 用于分档、`q()` 用于筛选项）：

```js
// 26-huasheng-shiye-A（事业单位A，满分150）：
[0, 90, 105, 120]
// 其余常规套卷（满分100）：
[0, 60, 70, 80]
```

若云端 `filteredQuestionStats` 里已有别的档位，以云端为准。标签格式：`0 → "全员"`，其余 `">" + 分数`。

切换后 `currentScoreFilter` 变化，`questionStats` 换成对应档位的分布。

#### 排名计算

```
calculateRankPercent(openId, examId, score)
  → 拉 exam_rank_stats
  → applyRankSnapshot: 算 rank / percent / totalSubmissions（并缓存 _radarSnapshot）
  → 有缓存则先用缓存（updateLocalCache）
  → 失败时 retryRankingLoad（15 秒节流）
```

#### 分享图（v78 起四种样式 + 预览弹层）

| 类型 | 用途 |
|---|---|
| `长截图` | 完整报告，存档 |
| `精简图` | 只放分数，朋友圈 |
| `细节图` | 分数 + 板块，群聊 |
| `能力图` `[v78 新增]` | 450×≥600 的「能力报告」长图，含雷达图 |

v78 的交互链路变了：点 `保存图片` **不再直接弹系统 ActionSheet**，而是打开页内预览弹层
（`图片预览` / 样式 Tab / `点图片可放大` / `保存到相册` / `×` 关闭）。
生成中显示「正在生成图片…」，失败显示「生成失败，点此重试」。四种样式各自缓存临时图，切回不重画。

### 3.3b 赞赏页 `pages/support/support` `[v78 新增]`

**作用**：唯一变现页。微信虚拟支付赞赏，从首页「💰 打赏开发者」进入。

#### 结构

1. 卡片式 Hero：`行测小助理` / `谢谢你的支持` / 旋转卡片里的 `♥`
2. `赞赏金额` 单选组：每档 = 圆点 + 插图 + 名称 + `¥价格`
3. 支付按钮：iOS `Apple 内购 ¥<价>` / 安卓 `微信支付 ¥<价>` / 模拟器 `请用手机扫码测试支付` / 未选 `请选择赞赏金额`
4. 回执区（支付中 / 结果 / 失败原因）
5. `查询支付结果`（有待确认订单时出现）

#### 交互链路

```
首页「💰 打赏开发者」
  → supportPayment{catalog}           拉商品目录（价格由服务端下发）
  → 选档
  → wx.login() 拿 code
  → supportPayment{create}            下单，返回 orderId + payment 参数
  → 先落盘 supportPendingOrder        （防杀进程丢单）
  → wx.requestVirtualPayment(payment) 拉起支付
  → supportPayment{status}            查单，轮询确认
```

#### 值得注意的设计

- **商品档位的插图是情绪化的**：鸡蛋、雪碧、`666`、`一起上岸`——把金额档位包装成俏皮话，
  而不是标准的 `¥6 / ¥18 / ¥68` 价格表。
- **iOS 走 Apple 内购**，安卓走微信支付，文案自动分叉。iOS 需微信 ≥ 8.0.68。
- **失败诊断是给开发者用的**：测试构建下可复制「设备 / 微信版本 / 基础库 / 错误码 / 详情」，
  且会把 ≥28 位的密钥串脱敏成 `[已隐藏]`。正式包不展示详情。
- **iOS 区域错误有专向引导**：命中 App Store 区域错误时提示去「媒体与购买项目」切换账号。
- **补单**：`onShow` 发现未完成订单会自动查单，覆盖「付完款杀进程」的场景。

### 3.6 数学计算（百化分训练）

#### ① 菜单 `pages/math-tools/menu/menu`

只有一个入口：百化分训练。（535 字节，几乎是空壳）

#### ② 训练 `pages/math-tools/percentage/percentage`

```
data: {
  question, denominator, inputValue,
  logs: [], startTime, timeString, timer, isRunning,
  correctCount, totalCount,
  showHistory: true,
  mode: "forward",           // forward / reverse
  questionQueue: []
}
```

**出题池（写死）+ 两条去重规则**：

```js
// 正向：1/n → 百分比
主池 [6,7,12,13,14,15,16]           出 6 题
次池 [8,9,11,17,18,19]              出 3 题
难池 [2,3,4,5,10]                   出 1 题

// 反向（百分比 → 1/n）额外加：
[16.7,14.3,8.3,7.7,7.1,6.7,6.3]
[12.5,11.1,9.1,5.9,5.6,5.3]
[100,50,33.3,25,20]
```

出题后洗牌，再校验两条约束（最多重试 100 次）：

1. **同一个分母最多出现 2 次**
2. **相邻两题不能是同一个数**

不满足就整组重抽。这个细节说明作者确实做过题——相邻重复会让人产生"是不是卡了"的错觉。

**判定规则**：误差 ≤ 2%

```js
correct = Math.abs((input - actual) / actual) <= 0.02
```

**键盘**：单字符输入，限 6 位，支持 `.` / `del` / `clear`，**5ms 防连击**（`lastTapTime`）。

**模式切换**：`onReversePractice` 弹 toast「切换到反向模式」并重开一局。

#### ③ 结果 `pages/percentage-result/percentage-result`

- 显示 `logs`（每题：题目 / 我的答案 / 正确答案 / 对错）+ `timeString` + `score`
- `onRetry` 再来一局

## 5. 产品设计手法拆解

### 5.1 它做对的三件事

**① 把"录入"这件事做到了极致**

同一件事给了三条路径：
- 手点（最基础）
- 扫描（效率最高，但要求专用答题卡）
- （隐性地）通过 `历史` 复用旧记录

扫描链路投入了 7 个模块、陀螺仪、四角检测、质量判定、隐私协议——**这是整个产品的技术护城河**，也是竞品最难抄的部分。

**② 用"群体参照"制造复访动机**

三层递进：

```
名次（1002 / 1064）→ 我在哪
百分位（超越 5.8%）→ 我比多少人强
逐题分布（A 5% / D 53%）→ 这道题大多数人怎么选
```

第三层是关键：它把"考试"变成了"共同体验"。用户会想"原来这题 53% 的人都选 D"，这种信息只有平台能给。

**③ 用彩蛋建立情感连接**

转盘 + 短信段子 + 每日励志弹层 + 语音。这些**不产生任何功能价值**，但让工具有了"人味"。独立开发者的个人色彩（"from独立开发者"）贯穿始终。

### 5.2 它做错的三件事（直接导致"用不懂"）

**① 三层入口，没有任何导航线索**

```
显性：首页首屏（套卷）
半显性：首页下方滚动区（工具）
隐性：长按标题输密码（管理）
```

用户不知道"下面还有东西"，更不可能知道"长按有东西"。而工具区需要滚动才能看到，**首屏完全没有提示**。

**② 18 个页面，一条返回路径**

没有 tabBar，没有全局导航。从一个工具页回主流程，要连按返回。

**③ 77 处 toast 代替了状态设计**

真正的问题不是 toast 多，而是**大量操作没有持久状态**：
- 扫描失败只有一句 toast，用户不知道下一步做什么
- 榜单加载失败只有 toast，没有重试入口（部分页面有）
- 保存预设失败只有 toast

## 6. 为什么用户会觉得用不懂

把上面的观察收敛成具体原因：

| # | 问题 | 证据 | 影响 |
|---|---|---|---|
| 1 | **入口无层级** | 主流程 / 工具 / 管理三层混在首页，无视觉分区 | 用户不知道产品边界在哪 |
| 2 | **无全局导航** | 18 页只有 `‹` 返回 | 迷路后只能一路退回首页 |
| 3 | **工具区在首屏外** | `常用工具` 在套卷列表下方，需滚动 | 大概率永远看不到 |
| 4 | **扫描模式前置条件重** | 必须先下载 A4 答题卡 → 打印 → 填涂 → 拍照 | 用户点了"扫描"才发现没卡 |
| 5 | **广告门打断主流程** | 扫描交卷必须看完广告 | 最关键时刻被打断 |
| 6 | **状态反馈碎片化** | 77 处 toast，无持久状态 | 用户无法判断"现在到哪了" |
| 7 | **同名概念混用** | `手动录入` vs `答题` vs `逐题`；`历史` vs `答题记录`；`总用时` vs `总时间` | 认知负担 |
| 8 | **隐藏功能无提示** | 长按密码进后台；每日弹层 | 功能存在但用户不知道 |
| 9 | **分享断层** | 18 页只有 6 页能分享 | 传播路径断在关键页 |
| 10 | **空态与错误态不统一** | 各页文案、按钮、位置都不同 | 出错时用户不知道怎么办 |

## 7. 可以直接照搬的七条

这一节是给设计/开发的**可执行清单**，每条都标注了在当前原型里的落点。

| # | 手法 | 为什么值得抄 | 落到我们哪儿 |
|---|---|---|---|
| 1 | **选中 = 整块深色反转**，不用描边变色 | 移动端小屏上，色块对比比描边强一个数量级，弱光/强光都可读 | 答题选项、榜单维度、筛选 chip 统一成这条规则 |
| 2 | **长按 + 进度环 + 触觉** 替代二次确认弹窗 | 不可逆操作（结束计时、清空）用一次长按解决，比弹两次窗顺手；进度可视化让用户知道"要按多久" | 删除记录、清空草稿可以换成 800ms 长按 |
| 3 | **大数字 + 小标签** 的统计排版 | 数字 56–120px、标签 24px，一屏能读完关键信息，不需要图表 | 成绩页、我的记录已经接近，可再放大一号 |
| 4 | **三段式流程条**（圆序号 + 箭头） | 跨设备/多步骤任务一句话讲不清，图示可以 | FB 工具那种"复制→打开→安装"，适用于任何引导页 |
| 5 | **底部抽屉 + 拖拽手柄** | 比整页跳转轻，比弹窗重；答题卡、选项类内容最适合 | 答题卡在手机上已经用了，可以统一其它"选择"场景 |
| 6 | **胶囊分段控件**（圆角 999 + 深色选中） | 二选一/三选一的通用解，横向空间占用小 | 榜单维度切换、分数筛选 |
| 7 | **误差容忍判定**（百化分 ±2%） | 训练类场景不该用精确匹配，容错让体验不那么挫败 | 如果做速算/心算类训练，直接复用这个阈值思路 |

## 8. 必须避开的五个坑

| # | 坑 | 具体表现 | 我们应该怎么做 |
|---|---|---|---|
| 1 | **功能入口无层级** | 主流程、工具、管理三层全塞首页 | 明确分区，且**首屏就给全局导航**（我们有 tabBar，已经对了） |
| 2 | **把工具当主功能** | 首页下方挂了 4 个和记分无关的工具 | 工具要么独立成页签，要么干脆不做 |
| 3 | **前置条件藏在流程中间** | 点"扫描"才发现要先下载打印答题卡 | 入口上直接写清前提，或先给"没有答题卡？手动录入"的并列选项 |
| 4 | **广告门 / 强制分享** | 扫描交卷必须看完广告 | 我们的产品原则已明确禁止，保持 |
| 5 | **toast 代替状态** | 77 处 toast，失败后无重试入口 | 关键操作要有**持久状态 + 明确下一步**，不能只闪一句 |
