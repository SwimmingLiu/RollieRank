# 对照「行测小助理」：卷卷小榜六维优化建议

> 对照基准：`docs/ui-exploration/ios-v3`（refined-1112-v5，当前原型）
> 参考对象：`docs/xingce-miniprogram`（行测小助理 v78 解包 + 实机截图）
>
> 结论先给：**卷卷小榜在数据诚实度、报告深度、导出能力上领先；在分享通道、群体参照、录入效率上落后。**
>
> 六维全景按"该不该抄"分三类：**必须补的缺口**（分享、百分位、真实榜单数据）、**可以借的表达**（逐题分布、参照筛选、折叠）、**明确不抄的**（会员体系、竞争性文案、强制分享）。

---

## 0. 六个维度的总览

| 维度 | 卷卷小榜现状 | 行测小助理 | 差距判断 |
|---|---|---|---|
| 1 分数录入 | 逐题点选 + 键盘 + 批量粘贴（3 种格式）+ 标记/答题卡/跳题 | 逐题点选 + **摄像头扫描专用答题卡** + 答题卡弹层 + 逐题/分章双模式。两边都没有对方的强项 | 我们录入格式多、有键盘流；它有图像入口。**互补，不是替代** |
| 2 排行榜 | 真实计算（同卷同版本、个人最佳、并列名次、≥10 人可见），但参与者和内容来自 12 个 `demoEntries` 假数据 | 真实云端榜（`exam_rank_stats` 聚合），带 **超越 X% 对手** + **参考排名 X/Y** | 口径我们更严谨，**呈现和激励它更强**；我们缺"百分位"这一层表达 |
| 3 结果导出 | PNG 海报（3 种样式）+ 逐题 CSV + 全量 JSON 备份 | 只能存图片（canvas 海报） | **我们更全**；缺正式 PDF 成绩单 |
| 4 分享 | 无 `navigator.share`；只有"复制同卷链接"+"保存 PNG"；无微信/小程序回流 | 原生的 `onShareAppMessage` / `onShareTimeline`，卡片带标题、可回落到同卷 | **最大短板**：我们没有任何原生分享通道 |
| 5 展示 | 得分卡 + 环形得分率 + 最弱 3 项 + 九板块进度条 + 同卷趋势图 | 得分卡 + 逐题选项分布（百分比/人数/正确答案绿底）+ 英雄榜 + 章节折叠统计 | 我们偏"个人诊断"，它偏"群体参照"。**逐题选项分布是我们完全没有的杀手锏** |
| 6 个人中心 | 体验身份（昵称）+ 12 条历史 + 同卷趋势 + 认领/删除/备份 | 头像/昵称/历史/排行榜身份 + 微信登录 + 会员体系 | 我们结构完整但**没有账户体系**，身份随时丢 |

## 1. 分数录入

### 我们现在有什么
`src/views-practice.js:practiceView` + `src/app.js` 的 `bulk` 流程：

- 逐题 A–D 点选，`autoNext` 自动跳题
- 键盘 A–D / ←→ / Backspace
- **批量粘贴 3 种格式**：`ABCD-ABCD`、`1.A 2.B`、`1-5 ABCDA`，带预览和覆盖数量确认
- 答题卡按题型分组、进度环、跳题、待检查标记
- 草稿本机自动保存 + 保存失败告警

这一块已经比小程序强。小程序只有点选和答题卡弹层。

### 缺口
1. **没有图像入口**。小程序有完整的扫描链路：`utils/scan-session.js`、`utils/scan-guidance.js`、`utils/live-scanner.js`、`photo-frame.js`（四角打包）、`photo-quality.js`（质量判定）、`torch-preference.js`（补光偏好）、`scan-submit-ad.js`，页面层用 `markerPresence` 跟踪四个定位块、`gyro` 陀螺仪、`workerReady` 判断识别 worker 就绪，对着自己印的 A4 专用答题卡拍两张就能自动录入 130 题。这对"已经在纸上做过一遍、现在要录第二遍"的场景是数量级的效率差异——也正是我们产品的核心场景。
2. **录入后的校验反馈弱**。小程序在提交时会明确列出未答题号并支持逐题跳转；我们只有底部一句"还有 N 题未答"。

### 建议
| 优先级 | 动作 | 说明 |
|---|---|---|
| P1 | 提交前"缺题清单"改成可点跳转 | 复用小程序 `missing` 弹层：列出题号 chip，点一个跳到一题。改动小、收益直接 |
| P2 | 加"答题卡照片 → 选项"的离线辅助 | 不一定要做实时摄像头。先做**拍照后前端识别**（四角定位 + 网格切分），识别失败就退回手动。需要先做答题卡模板 PDF |
| P3 | 批量粘贴增加"从剪贴板自动读取" | 现在要手动粘贴，移动端可加一个 `navigator.clipboard.readText()` 按钮 |

## 2. 排行榜

### 我们现在有什么
`src/leaderboard.js` + `src/views-records.js:rankView`：

- 口径严谨：同机构/同期/同卷/**同规则版本**才算一个榜
- 每用户取最高分占 1 席；题型榜独立取各次最佳，允许来自不同答卷
- 竞赛排名 `1、1、3`；同分按达成时间排显示顺序
- 有效人数 < 10 时**隐藏公共名次**，只显示个人结果
- 总分榜 + 每个题型榜
- 领奖台 + 列表 + "我的同卷最佳"侧卡

### 对比：小程序强在哪
| 它的做法 | 效果 |
|---|---|
| **"超越 5.8% 对手"** | 比一个名次更能表达位置。名次 1002 会劝退，超越 5.8% 会让人想再来一次 |
| **"参考排名: 1002 / 1064"** | 分母给出参照系，避免"第 18 名"无法判断含金量 |
| **逐题选项分布**（A 5%/41人、D 53%/471人，正确答案绿底） | 把榜单从"人和人比"扩展到"我和所有人在这道题上的选择比"，是真正的差异化 |
| **三档分数筛选**（全员 / >60 / >70 / >80） | 让用户自己选参照群体，避免"和高分怪物比"的挫败 |
| 英雄榜前 3 名带头像 + 分数 + 柱状图入口 | 可点击、可展开，社交感强 |

### 建议
| 优先级 | 动作 | 说明 |
|---|---|---|
| P0 | **加百分位表达** | 榜单和个人报告都补"超过 X% 的练习者"。用 `(低于我的人数 / 有效人数)` 计算，与现有并列名次兼容 |
| P0 | **补分母** | 名次旁边永远带 `/ 有效人数`，别只显示"第 18 名" |
| P1 | **逐题选项分布** | 依赖云端聚合。模型里加 `questionChoiceStats: { versionId, questionNumber, counts: {A,B,C,D,blank} }`，报告页渲染成四格条形。这是最值得抄的一个功能 |
| P1 | **参照群体筛选** | 榜单加"全员 / ≥60 / ≥70 / ≥80"分段，复用现有 `dimension` 切换的交互 |
| P2 | 领奖台视觉 | 我们现在是平铺列表，小程序和 refined 原型都有立体领奖台 |

### 一个必须说清的问题
`docs/ui-exploration/ios-v3/app.js:83,85,156,162` 里 `rank:18, participants:236` 是**写死的**，`RANK_FIXTURES` 是 7 条固定假数据。当前原型的榜单看起来完整，但**没有任何一条来自真实计算**。而 `src/leaderboard.js` 里已经有一套能跑的 `rankEntries`，两者没接上。这是原型和实现之间最需要先补的缝。

## 3. 结果导出

### 我们现在有什么
- `src/poster.js`：3 种海报（成绩摘要 / 题号色块 / 答案对照），canvas 实际生成 PNG
- 逐题 CSV（`resultCsv`）
- 全量 JSON 备份 / 恢复（`export-data` / `restore-data`）
- 纠错反馈 `.txt`

### 小程序
只有 canvas 生成一张图存相册。导出能力明显弱于我们。

### 建议
| 优先级 | 动作 | 说明 |
|---|---|---|
| P2 | **PDF 成绩单** | 现在只有 PNG 和 CSV。纸质党要打印/存档，PDF 比 PNG 合适。用同一套 canvas 排版输出多页即可 |
| P2 | CSV 增加题型小计行 | 现在是逐题，缺题型汇总，Excel 里还要自己算 |
| P3 | 海报加"二维码回流" | 小程序海报右下角带小程序码。我们可以在海报角上放一个同卷链接二维码，扫码直接进同卷答题 |

## 4. 分享

**这是六个维度里差距最大的一项。**

### 现状
- `src/` 里**没有 `navigator.share`**（refined 原型 `app.js:213` 的 `invite` 有，但那是原型，没进 `src/`）
- 没有 `og:` / `twitter:` meta，`index.html` 只有 description 和 title → 分享到微信/微博不会生成卡片
- 没有小程序、没有公众号回流路径
- 唯一路径：手动保存 PNG → 用户自己去发

### 小程序
- `onShareAppMessage` / `onShareTimeline` 是一等公民，每页都实现了
- 分享卡片标题是动态的：`"我正在挑战《xxx》，你也来试试？"`，路径带 `examId`
- 首页分享是通用引流文案

### 建议
| 优先级 | 动作 | 说明 |
|---|---|---|
| **P0** | **补 `navigator.share`** | 移动端浏览器支持 Web Share API。一行代码换一个原生分享面板，是当前性价比最高的改动 |
| **P0** | **补 Open Graph meta** | `og:title` / `og:description` / `og:image`。没有它，任何社交平台分享都是裸链接 |
| P1 | **动态分享文案** | 按成绩生成标题：`"这套卷我拿了 72.50，超过 82% 的练习者"`。小程序就是这么做的 |
| P1 | **分享落地页** | 现在分享出去的链接直接进应用首页，没有承接。应做一个只读的同卷公开页（不含个人答案），带"我也来练"入口 |
| P2 | 微信生态回流 | 长远看必须有。小程序或公众号 + 扫码进同卷，是小程序那套跑通的核心增长环 |

### 一个设计判断
小程序把分享做到极致（每页都能分享、文案动态、带回流），是因为**它的商业模式依赖传播**。卷卷小榜定位是"练习记录工具"，不需要照抄这套激进增长，但 **P0 两项（Web Share + OG meta）属于基础能力缺失**，不是增长优化。

## 5. 展示

### 我们现在有什么
`reportView` + `statsView`：

- 得分卡：大字分数 + 环形得分率 + 正确/错误/未答三栏
- 较上次同卷的分数差（`+2.5 分` / `-1.0 分`）
- 最弱 3 项题型（可展开全部），带上次对比
- 九板块进度条 + 得分/满分 + 得分率
- 同卷得分率趋势折线图（最多 12 次）
- 逐题对照表（我的/参考/结果，可筛错题、按题型筛、复制错题号）

### 对比
| 维度 | 我们 | 小程序 |
|---|---|---|
| 分数呈现 | 环形 + 大字 | 大字 + 暖色卡片，无环 |
| 题型 | 进度条 + 上次对比 | 折叠卡片 + 胶囊 `0/15题 \| 正确率 0.0%` |
| 群体参照 | 只有名次 | 名次 + 百分位 + **逐题选项分布** |
| 趋势 | 有（同卷折线） | **无** |
| 逐题明细 | 有（我的/参考/结果） | 无 |
| 情感表达 | 克制的书面语 | "超越 5.8% 对手""英雄榜""🏆" |

### 判断
我们展示层**信息更全、更专业**，但**情绪浓度更低**。这不是缺点——"不推断上岸概率""不宣传为真实模考实力"是产品原则。但有两处可以借：

| 优先级 | 动作 | 说明 |
|---|---|---|
| P0 | **逐题选项分布** | 见第 2 节。它既是展示也是参照，是目前最缺的一块 |
| P1 | **报告首屏加"这次最重要的一句话"** | 现在首屏是数字。可以加一行结论式描述，比如"资料分析比上次高了 12%，是这次进步最大的一项"。注意：只能描述数据，不能推断 |
| P2 | 板块折叠 | 九板块全展示在手机上偏长。小程序用折叠卡，我们可以默认展开前 3 项 |

## 6. 个人中心

### 我们现在有什么
`meView`：

- 体验身份（16 字昵称，本机）
- 累计练习 / 最高得分率 / 平均得分率
- 完整历史（可筛套卷、标个人最佳、删除）
- 未认领成绩提示 + 认领
- 备份 / 恢复 / 隐私说明 / 纠错 / 删除全部

### 小程序
- 微信授权登录，头像昵称来自微信
- 会员体系（`vip/`、`memberBuy/`、`orderList/`）
- 我的订单、客服、绑定手机
- 课程切换（`switchAccounts`）

### 判断
它的账户体系是**商业化需要**（卖会员），我们没有这个诉求，**不建议照抄**。但有两处真实问题：

| 优先级 | 动作 | 说明 |
|---|---|---|
| **P0** | **身份丢失风险** | 现在清浏览器数据 = 身份和历史全没。虽然提供了 JSON 备份，但用户不会主动备份。至少要：① 首次设置昵称时提示"记录只存在这台设备的浏览器里"；② 更醒目的定期备份提醒 |
| P1 | **认领流程前置** | 现在是先练后认领。应在首次进入时就给"要不要现在就设个昵称"的轻提示，减少后期认领成本 |
| P2 | 数据可携带 | 备份是 JSON，普通用户不会用。可考虑生成一个"成绩卡"分享链接（只读），既是分享也是另一种形式的数据留存 |

## 7. 按优先级汇总

### P0 — 基础能力缺失，应尽快补

| # | 动作 | 现状证据 | 依赖 |
|---|---|---|---|
| 1 | `navigator.share` + Open Graph meta | `grep navigator.share src/` 零命中；`index.html` 无 `og:` | 无，纯前端 |
| 2 | 榜单百分位 + 分母 | `src/` 无 percentile 表达（grep "percentile\|超过\|高于" 无相关命中） | 无，基于现有 `rankEntries` |

10. 报告首屏结论句（展示，§5）
11. 认领流程前置（个人中心，§6）

### P2 — 锦上添花
12. 拍照识别答题卡（录入，§1）
13. PDF 成绩单（导出，§3）
14. 海报二维码回流（导出，§3）
15. 立体领奖台（排行，§2）
16. 板块折叠（展示，§5）

## 8. 三个不建议照抄的地方

| 小程序做法 | 为什么不建议 |
|---|---|
| "超越 X% 对手"这类竞争性文案 + 英雄榜 + 勋章化 | 与"不宣传为真实模考实力""重复作答有记忆效应"的产品原则冲突。百分位可以加，措辞要中性（"高于同卷 X% 的练习记录"） |
| 会员体系、订单、客服、绑定手机 | 没有商业化诉求，会稀释"练习记录工具"的定位 |
| 分享解锁 / 强制分享 | 产品原则里明确"不强制分享解锁报告"，保持 |

---

## 9. 一句话总结

小程序的强项集中在**录入效率（扫描）、群体参照（百分位 + 逐题分布）、传播（原生分享）**；
卷卷小榜的强项集中在**口径严谨、报告深度、数据可控（导出/备份/删除）**。

最该补的不是功能数量，而是三处**结构性缺口**：真实榜单数据没接上、分享通道完全没有、群体参照维度缺失。
