# 卷卷小榜｜行测打分产品方案

> 文档定位：产品 / UI / 研发共同依据；仅定义产品，不含本次代码实现。  
> 核心路径：**选机构与套卷 → 录答案 → 自动估分 → 看题型短板 → 同卷比较 → 分享 / 复盘**

## 1. 产品定义

| 项目 | 方案 |
|---|---|
| 产品定位 | 面向考公备考者的**答题卡估分与练习记录工具**，不是完整题库或真实模考系统 |
| 核心用户 | 多次刷机构套卷、需要快速核分与观察题型表现的考生 |
| 核心价值 | 免手工核分；适配各机构规则；沉淀练习记录；提供同卷参照 |
| 产品形态 | 保留现有 H5；新增微信小程序；独立受控录入入口，后续补轻量 Web 管理后台 |
| 内容边界 | 录入题号、选项、答案、题型、分值；MVP 不录入题干与解析；套卷内容须确认使用授权，下载 / 分享不代替授权 |
| 计分声明 | 按机构提供的评分参考估分；不宣称为官方真实考试成绩 |

**核心闭环**

`机构 → 考试项目 → 期数 → 卷别（按需） → 套卷 → 作答 / 粘贴答案 → 确认提交 → 服务端评分 → 题型报告 → 同卷练习榜 / 海报 → 历史复盘`

**默认决策**

- 首页按“**机构 → 考试项目 → 期数 → 卷别（按需） → 套卷**”组织；地市、副省等卷别不合并；无卷别差异时隐藏该层。题型只作为卷内分组、报告和榜单维度。
- 游客可作答并保存本机草稿、查看本机估分；登录后可认领历史。只有登录后的服务端有效提交可参与排行。
- 同一套卷可有多次作答；历史全部保留，公共榜为“**个人最佳练习榜**”。
- 不跨机构、考试项目、期数、卷别、套卷或规则版本混排。

## 2. 信息架构与用户流程

### 2.1 页面结构

```text
小程序底部：首页｜排行榜｜我的
H5 保留：套卷选择｜答题卡｜成绩报告｜逐题明细 / CSV

首页
└─ 机构
   └─ 考试项目
      └─ 期数
         └─ 卷别（按需） → 套卷详情 → 答题 → 提交确认 → 结果报告
                                      ├─ 成绩海报
                                      ├─ 同卷排行榜
                                      └─ 逐题明细（权限内）
我的 → 登录 / 隐私｜答题历史｜套卷统计｜本机记录认领
管理端 → 机构 / 考试项目 / 期数 / 卷别 / 套卷｜导入校验｜试算复核｜发布 / 下线｜修订记录
```

### 2.2 三条主流程

| 流程 | 步骤 | 关键反馈 |
|---|---|---|
| 首次作答 | 选卷 → 查看规则 → 作答 → 漏答确认 → 提交；游客本机估分，登录后服务端评分并入榜 | 保存状态、未答题号、提交结果 |
| 分享回流 | 报告 → 预览海报 → 保存 / 转发 → 好友打开同卷详情 | 公开字段可勾选；不开放私人报告 |
| 登录沉淀 | 微信登录 → 选择认领本机答卷 → 云端去重 → 历史同步；首次服务端提交可选择入榜 | 明示认领范围；失败保留本地数据 |

## 3. 页面功能清单

| 页面 | 核心内容 | 主操作 / 必要状态 |
|---|---|---|
| 首页 | 机构、考试项目、期数、卷别筛选；套卷卡片含题数、满分、更新 / 勘误状态、最近成绩或草稿进度 | 最近作答置顶；开始 / 继续 / 看成绩；加载、空卷、失败重试 |
| 套卷详情 | 机构、期数、版本、题数、满分、题型题量、计分说明 | 开始 / 继续 / 看历史；旧版、下线提示 |
| 答题页 | 当前题号与题型；实际选项；答题卡；已答进度；自动跳题 | 单题选择、跳题、清空、批量粘贴；自动保存 |
| 提交确认 | 已答 / 未答数；漏答题号；计分提示；参与排行选择 | 返回补答、确认提交；未答确认、防重复点击 |
| 结果报告 | 总分 / 满分；得分率；答对 / 答错 / 未答；题型分析；排名摘要 | 看明细、再答、海报、榜单；评分中 / 排名更新中 |
| 成绩海报 | 总分、题型概览、机构期数、匿名昵称、小程序码；名次和日期可选 | 预览、保存、转发；生成失败、相册授权拒绝 |
| 排行榜 | 当前套卷与版本；总分 / 题型 Tab；有效人数；更新时间；本人卡片 | 切卷、切题型、看本人；空榜、样本不足、退出榜 |
| 我的 | 微信登录；匿名设置；本机记录；隐私与纠错入口 | 登录、认领、退出榜；游客 / 无记录状态 |
| 答题历史 | 时间倒序；机构期数筛选；分数 / 满分、版本、提交时间 | 查看成绩快照、再次练习；分页、同步失败 |
| 套卷统计 | 同卷同版本的次数、最高 / 最近 / 平均分；题型趋势 | 切换套卷；单次仅展示基线，跨版本分段 |
| 管理端 | 机构 / 考试项目 / 期数 / 卷别 / 套卷配置；表格导入；逐行错误；整卷预览与试算 | 草稿、复核、发布、下线、复制修订；操作留痕 |

### 答题体验底线

- 套卷卡片默认收起，展开后展示题型构成、计分说明、历史成绩和同卷榜单。
- `NEW` 仅用于近期新卷；答案修订单独显示“已勘误”，两者不可混用。
- 保留现有 H5 的**批量粘贴、逐题答案对照、CSV 导出、独立本地草稿**。
- 选择后立即保存；退出、刷新、进程中断后可恢复；漏答题号可一键定位。
- 提交答卷只读；“再次作答”创建新记录，不覆盖旧卷。
- 不在提交前展示或下发标准答案。

## 4. 数据与计分规则

### 4.1 核心数据模型

| 对象 | 关键字段 | 约束 |
|---|---|---|
| 机构 `institution` | id、名称、排序、状态 | 机构停用不影响历史 |
| 考试项目 `exam_project` | id、机构 id、考试类型、年份 / 半年、状态 | 国考、事业单位 A 类等 |
| 期数 `period` | id、考试项目 id、期次编码、名称、状态 | 项目内期次唯一 |
| 套卷 `paper` | id、期数 id、卷别编码、标题、状态 | 地市 / 副省等卷别独立；无卷别用默认值 |
| 规则版本 `paper_version` | id、套卷 id、版本号、题数、满分、状态、发布时间 | 发布后冻结；答卷与榜单绑定此 id |
| 题型 `question_type` | id、稳定编码、名称、父级、排序 | 全局字典复用；判断推理可有子题型 |
| 题目 `question` | 版本 id、题号、选项、答案、题型 id、单题分 | 版本内题号唯一；每题只归一个题型 |
| 用户 `user` | id、微信身份、匿名昵称、隐私设置 | 不强制手机号或真实姓名 |
| 答卷 `attempt` | id、用户 / 游客 id、版本 id、状态、提交时间、提交令牌 | 每次作答独立；提交幂等 |
| 作答 `answer` | 答卷 id、题目 id、所选答案 | 原始选择不被成绩覆盖 |
| 成绩 `score_result` | 答卷 id、总分、满分、逐题 / 题型快照、计分器版本 | 不只保存总分 |
| 榜单 `rank_entry` | 版本、维度、题型、用户、代表答卷、名次、人数、更新时间 | 可按有效成绩重建；原子发布 |
| 审计 `audit_log` | 操作人、对象、前后差异、时间、原因 | 导入、发布、修订、撤榜留痕 |

### 4.2 套卷配置与发布

**支持规则**

| 层级 | 示例 | 优先级 |
|---|---|---|
| 卷级默认分 | 全卷每题 1 分 | 低 |
| 题型统一分 | 言语理解每题 0.8 分 | 中 |
| 单题自定义分 | 第 125 题 1.2 分 | 高 |

- MVP 仅单选、固定分值；答对得该题分，答错 / 未答 0 分，不倒扣。
- `总分 = Σ 单题得分`；`满分 = Σ 单题答对分值`；不默认满分 100。
- `得分率 = 得分 ÷ 满分`；`正确率 = 答对题数 ÷ 总题数`，两者分别展示。
- 分值以定点小数计算，展示时再格式化，避免浮点累计误差。
- 发布前校验：题号连续且唯一、选项合法、答案属于选项、题型有效、规则覆盖完整、分值合理、题数与满分对账一致。
- 导入失败定位到行 / 字段；整批失败，不允许半套卷发布。发布前预览、全对 / 全错 / 混合试算并复核。

### 4.3 版本、修订与游客认领

| 场景 | 统一规则 |
|---|---|
| 答案或分值纠错 | 创建新规则版本；旧成绩、报告与榜单保持原口径，默认不重算；新版开启独立榜单 |
| 题量、题序或题目含义变化 | 新建套卷，不作为普通版本修订 |
| 已开始作答时发布新版 | 原草稿仍绑定原版；原版停止新提交时明确提示，不静默搬运答案 |
| 游客登录 | 按本机 `guestId + attemptId` 展示待认领记录；用户确认后认领并同步历史；服务端有效提交可入榜 |
| 跨端重复认领 | 同一提交令牌只同步一条成绩；冲突保留各次记录，不覆盖历史 |
| 重复点击 / 断网重试 | 返回同一提交结果；不重复生成成绩或榜单名额 |
| 服务端失败 | 不生成伪成绩；保留草稿与提交凭证，可重试 |

## 5. 结果报告与海报

### 5.1 报告信息层级

1. **本次成绩**：得分 / 满分、得分率、正确 / 错误 / 未答、提交时间、版本。
2. **题型分析**：题型｜得分 / 满分｜得分率｜答对 / 题数｜较本人上次（仅同版）。
3. **同卷参照**：个人最佳名次 / 有效人数；本次未刷新最佳时明确标注。
4. **复盘入口**：本人答案对照、错题筛选、CSV；无解析内容时不生成“AI 建议”。

> 低分题型提示仅作数据描述，如“资料分析本次得分率最低”；不推断上岸概率。

### 5.2 海报规范

| 区域 | 默认内容 |
|---|---|
| 主视觉 | 本次得分 / 满分、“同卷练习成绩” |
| 辅助 | 机构 + 期数、题型得分率概览 |
| 身份 | 默认匿名；头像、昵称、名次、日期由用户主动选择 |
| 回流 | 小程序码进入同卷公开详情；不进入私人报告 |
| 禁止 | 逐题答案、openid、手机号、可定位私人答卷的参数 |

- 生成前预览公开字段；拒绝相册权限不影响网页报告与会话分享。
- 成绩修订后，小程序内打开对应历史版本快照；答案或分值错误另发更正说明。已保存的旧图片无法自动撤回，应提示重新生成。

## 6. 排行榜

### 6.1 统一口径

| 规则 | 方案 |
|---|---|
| 排名范围 | 同机构、同期、同套卷、同规则版本；无跨卷总榜 |
| 榜单类型 | 总分榜 + 当前卷全部题型榜 |
| 入榜条件 | 登录、有效提交、主动参与排行；异常 / 撤回 / 测试卷排除 |
| 总榜成绩 | 每用户取最高总分的有效答卷，仅占 1 席 |
| 题型榜成绩 | 每题型独立取历史最高得分率；展示得分 / 满分、得分率、达成时间 |
| 同分 | 并列同名次，采用竞赛排名 `1、1、3`；达成时间只影响列表显示顺序 |
| 有效人数 | 该榜去重后的有效用户数，不是作答次数 |
| 零分 | 可保留本人成绩；默认不进入公开题型榜，公开分母保持一致 |
| 样本不足 | 默认有效用户少于 10 人时隐藏公共名次与“超过比例”，仅显示个人结果 |
| 更新 | 显示更新时间；撤榜 / 退出后原子重算，不混用新旧名次 |

**名称固定为“同卷练习榜”**：重复作答存在记忆效应，不宣传为真实模考实力。  
总榜与题型榜可分别来自不同次作答；页面必须标明“个人各次最佳”，不能拼接成一次虚构成绩。

## 7. 个人中心与历史统计

| 模块 | 展示 | 口径 |
|---|---|---|
| 账户 | 登录状态、匿名昵称、公开设置、本机待认领数 | 不强制手机号；可退出榜 |
| 历史列表 | 套卷、得分 / 满分、得分率、版本、时间、最佳标记 | 每次提交均保留；仅本人可见 |
| 单卷统计 | 作答次数、最高 / 最近 / 平均分、首末次差值 | 仅同卷同规则版本；至少 2 次才显示趋势 |
| 题型统计 | 各题型得分率、最近表现、样本卷数 | 同版直接比较；跨卷须标明样本与聚合口径 |
| 跨卷总览 | 练习次数、完成卷数、按时间排列的得分率 | 不计算跨卷总排名，不宣称等值进步 |
| 数据管理 | 导出、删除记录、注销账号、纠错反馈 | 删除 / 注销后移除公开榜并保留必要审计 |

## 8. 异常、隐私与公平性

| 场景 | 产品反馈 / 规则 |
|---|---|
| 有漏答 | 展示数量与题号；确认后按 0 分提交 |
| 离线 / 保存失败 | 明示“仅本机保存”；不清空答案，恢复网络后重试 |
| 提交中 / 评分中 / 排名更新中 | 分状态展示；排名延迟不影响先生成成绩 |
| 套卷下线 | 首页不展示新入口；本人历史报告仍可访问 |
| 版本不同 | 明示版本与满分；不直接比较趋势或排名 |
| 异常高频 / 极短时长 | 仅作风险信号，限流或复核；不凭单一指标判作弊 |
| 公开信息 | 默认匿名；完整答卷仅本人；服务端最小权限与审计 |
| 分享 | 不强制分享解锁报告；不在分享参数中携带身份或私人成绩 id |

## 9. MVP 与版本路线

| 阶段 | 范围 | 退出标准 |
|---|---|---|
| V0.1 规则配置化 | 现有 12 套 H5 数据导入新模型；动态题数 / 题型 / 分值；导入校验与人工验算样例 | 至少 3 套差异样卷通过；全对 / 全错 / 全空 / 混合结果一致 |
| V1.0 完整闭环 | H5 保留；新增小程序；云账号、认领、服务端评分、报告、练习榜、海报、历史、受控导入 | 选卷到历史回看无阻断；双端同源；客户端无法读答案或写分数 |
| V1.1 运营提效 | 轻量后台、复制上期、版本差异预览、发布记录、海报模板、运营看板 | 运营无需改库即可导入发布；错误可定位 |
| V1.2 学习增强 | 题干 / 解析、错题本、计时练习、跨期同口径趋势 | 先验证复访需求；新功能不改变既有成绩口径 |

**MVP 非目标**：多选 / 主观题、负分、任意动态公式、AI 学习建议、跨卷总榜、好友 PK、支付广告、完整多租户后台。

## 10. 验收标准与指标

### 10.1 上线验收

- [ ] 不同题数、题型集合、满分、分值的样卷可独立配置并正确评分。
- [ ] 导入缺号、重号、非法答案、未知题型、规则缺漏、满分不一致时禁止发布。
- [ ] 全对、全错、全空、混合作答与人工验算一致；报告、海报、历史分数一致。
- [ ] 退出、刷新、断网、进程中断后草稿不丢；漏答提交有二次确认。
- [ ] 双击、重试、跨端认领不生成重复成绩；每次主动重考均保留历史。
- [ ] 提交前无法读取标准答案；客户端不能写入总分、名次或他人记录。
- [ ] 总榜 / 题型榜去重、并列、样本门槛、退出榜与更新时间符合口径。
- [ ] 修订后旧成绩可复现；新旧版本不混榜；结构变化不会覆盖旧卷。
- [ ] 海报可保存与转发，拒绝授权有反馈；默认匿名且不含私人链接。
- [ ] H5 批量粘贴、逐题明细、CSV、本地草稿无回归；手机端核心流程可用。

### 10.2 核心指标

| 指标 | 公式 |
|---|---|
| 计分准确率 | 人工验算一致的有效提交数 ÷ 抽样提交数；上线验收要求 100% |
| 选卷转化率 | 开始作答人数 ÷ 套卷详情访问人数 |
| 作答完成率 | 有效提交数 ÷ 开始作答数，按机构 / 期数拆分 |
| 提交成功率 | 成功生成成绩的提交数 ÷ 有效提交请求数 |
| 报告分享率 | 生成海报或会话分享人数 ÷ 报告查看人数 |
| 分享回流提交率 | 分享回流后的有效提交人数 ÷ 分享回流访客数 |
| 7 日复答率 | 提交后 7 日内再次开始作答人数 ÷ 当期提交人数 |
| 成绩纠错率 | 确认更正成绩数 ÷ 有效提交数，同时记录原因与影响范围 |

## 11. 技术衔接建议

| 层 | 建议 |
|---|---|
| 用户端 | 原生微信小程序 + 保留 H5；共用套卷、提交、报告、历史与榜单接口 |
| 服务端 | 微信云开发：云函数 + 云数据库 + 云存储；H5 通过受控 HTTP 接口访问 |
| 计分 | 共享评分核心 + 服务端权威评分；客户端不得上传总分；提交前私有答案隔离 |
| 配置 | 将现有固定 130 题规则适配为版本化题目配置；新增卷不再写死题数与分值 |
| 身份 | 小程序微信登录；H5 采用微信授权或扫码绑定，统一用户映射 |
| 草稿 | 本地离线保存；云端按 `attemptId` 同步；认领与提交均幂等 |
| 榜单 | 服务端聚合、按版本与题型建索引；按批次原子发布，缓存可重建 |
| 海报 | Canvas / 服务端生成；仅接收用户确认公开字段；私人报告始终鉴权 |
| 运维 | 导入 / 发布 / 修订审计；监控提交失败、评分异常、重复提交与分享失败 |

**现有资产处理**：当前 H5 的 12 套卷作为首批机构期数数据迁移；本地草稿经题号 → 题目 id 校验后导入。原有能力保留，不另写一套固定 130 题的小程序评分逻辑。
