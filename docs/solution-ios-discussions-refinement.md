# 本卷交流页面方案

报告固定操作栏提供评论图标和真实数量，点击进入本卷评论。页内先展示评论列表，输入入口固定底部；暂无评论时保留简短空态，读取失败可重试，未知数量不显示零。

发言复用现有 BottomSheet 的模态、焦点和关闭行为。面板打开后聚焦正文，初始两行，随输入增高至六行；输入框与发送按钮同排。照片图标直接选择图片，正文自动识别 HTTP 链接；长文可展开全屏。字数仅在接近上限时提醒。评论作者沿用用户昵称，编辑面板不重复身份展示；没有资料时使用「卷友」。

面板沿用暖纸色、珊瑚色和当前字号。视觉标题与独立底部发送区让位给输入条，弹层仍保留「发表评论」的可访问名称。取消通过遮罩或 Escape；附件较多时内容滚动，发送控件留在紧凑输入行。

评论布局采用用户参考中的头像、作者、正文、时间和回复，右侧用细线心形图标与紧凑数量呈现点赞。回复在主评论下缩进一级，回复他人时保留对象昵称；展开、分页与收起使用短按钮。专用 React 组件复用 beUI Card、Button 和现有讨论 Avatar，保持暖纸色、浅珊瑚与当前字体。列表与编辑器分离，更新互动不重建正在编辑的表单。

草稿按本机身份、试卷和回复对象分别保存在模块内存，关闭面板、切换路由和失败重试均保留。取消回复时切回独立的主评论草稿；再次回复原对象可以继续编辑。成功发表后才清空；发送期间锁定编辑，同内容重试复用标识，改内容或对象后使用新标识。

服务端依真实同卷提交凭证授权。点赞使用每个身份的布尔成员关系，重复请求与并发操作不重复计数；公开返回 `likedByMe` 与 `likeCount`，隐藏点赞身份。回复可以指向主评论或另一回复，统一归入主评论的 `rootId`，根列表与报告入口数量包含真实回复。回复分页使用独立游标，跨卷目标或游标不能串入当前讨论。

验证仅覆盖本模块、临时真实 API 和临时编译组件，使用实际 iOS 外壳和 iframe 的 320/390/430 画板。公共路由、bridge 和 vendor 由协调对话接入；模块交接列出三个 mount 导出及 `onModalClose` 约定。
