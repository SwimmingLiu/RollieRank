# 选岗与报告界面调整

个人记录的学习工具使用与原有卷卡一致的两张紧凑纸卡，分别进入报考岗位和成长分析。整卡可点，不再常驻解释段落和大块黑色选岗按钮。

岗位按实际招录信息逐级选择：招考项目 → 机构类别与考试类别 → 招录部门 → 用人单位 → 具体岗位。只有一个招考项目时直接进入类别；无有效分类或用人单位的来源按真实字段自然跳过，不能补造组织层级。顶部保留已选路径，点击任一层可返回修改，下级条件随之清除。当前层较长时提供就地搜索。具体岗位只先显示名称与原始编码，完整要求按需查看。

提交前选岗提醒只用一句说明和两枚等宽按钮「去选岗」「先提交」。关闭、Escape 和点遮罩返回答卷；关闭不会提交。选岗成功从原提交继续，最多一次。全部使用现有 beUI BottomSheet 与 Button。

报告保留原生估分、雷达与题型纸卡。首次没有可比记录时不放单点趋势和首刷说明卡；二刷用原生 VS 卡直观比较，至少三次时补充简洁曲线。完整筛选、趋势与逐次记录表放在独立成长分析页，使用图、指标和紧凑表，不常驻长段说明或技术规则编号。

答案纠错放到逐题对照页的独立按钮，反馈表单继续使用真实题号、建议答案与依据。报告不保留空的「答案反馈／修订0」卡。实际答案订正后，只按需显示能进入处理详情的状态。

本卷交流独立成页，卷名明确限定讨论范围。报告固定操作栏展示评论图标和真实数量；交流页先展示评论，输入栏固定底部，点按后再打开编辑器。昵称和头像直接使用用户资料，附件、录音按需展开。复用原媒体规范化和真实评论服务，不新增投票或未经请求的话题功能。

原生白／深灰、浅珊瑚、暖色纸卡和现有字体保持一致。此次选择紧凑双卡和逐级列表；不采用常驻大表单或系统原生下拉弹出层。数据不足时直接呈现适用的空态，不生成示例趋势。

## 后端层级接口

`GET /api/positions/hierarchy` 接受 `sourceId/categoryId/departmentId/unitId/q/page/pageSize`，也可用 `positionId` 恢复某岗位所在路径。返回 `{level,source,breadcrumbs,options,total,page,pages,autoAdvance}`。level为 source/category/department/unit/position；普通option为 `{id,label}`，末级option另外带 `positionId,code,position`，position保持既有完整岗位形状。breadcrumbs每项为 `{level,id,label}`，可附 `automatic:true` 表示没有有效分类的自然过渡。所有ID视为不透明字符串。

来源未指定时返回项目列表；source后选类别，category后选部门，department后选单位，unit后选岗位。只从所选父节点内列出子项；无效或跨层ID不能退回更宽范围。原有岗位ID和已选岗位保持不变。类别必须来自原Excel的机构类别与考试类别，规范展示副省级／地市级／行政执法类。已有无分类导入兼容并明确自然过渡，不能从专业或学历猜分类。

## 前端上下文扩展

保留前轮ctx。新增 `ctx.onModalClose(callback)`，返回取消订阅函数；callback收到 `{reason:'dismiss'|'complete'}`。用户关闭、Escape和遮罩是dismiss，模块主动ctx.closeModal是complete；媒体与待提交状态据此清理。

分析包装返回 `statsView(options)` 和afterRender；报告使用 `analytics-comparison` 既有挂载，由新组件渲染简洁真实对比。必要时可导出reportView，但不在结果页放完整分析表单。

讨论包装新增 `reportEntryView()`、`discussionView()`，在新页面名discussion内渲染完整交流，报告入口由包装自己处理点击ctx.navigate('discussion')。当前ctx.attempt在discussion同样返回当前真实答卷。编辑器由既有BottomSheet承载，列表与编辑器分开。复用原媒体工具，保持失败草稿及幂等提交。

纠错包装新增 `openFeedback(questionNumber?)`；ctx.attempt在details仍是当前真实报告。报告不再提供corrections-report空卡挂载；需保留订正提示时提供 `reportStatusView()`，无实际变化时返回空。原通知与授权审核保留。

最终必须在实际 `/ios-v3/` 外层页面及iframe验证类别→部门→单位→岗位、路径回退、短提醒的两按钮、取消不提交、保存不改ID、临时浏览不改个人选岗、原生VS/曲线/记录表、纠错和交流发言。检查320/390/430画板与桌面外层，保留真实截图。

## 后续页面批注

交卷后自动计分，答案审核订正后自动更新相关答卷。旧设计记录只保留静态「示例估分」标记，实际答案更正只在确有订正时显示。

记录页工具双卡之后，历史使用更紧凑的原生纸卡与单行筛选栏，搜索按需展开。机构、卷别、套号和真实成绩保持可辨，重复的长说明与大空隙收敛。

录答案的完成数／总题数移至卷身份右侧，保留细进度条，移除普通成功保存状态与信息图标。存储失败仍以必要的错误状态告知。答题卡改为题号与大答案分层的圆角网格，当前、已答与未答用位置和表面明确区分，完整题量均可访问。

答题卡组件与专用样式由纠错对话在原专项完成后承担，协调对话继续负责实际宿主、bridge和跳题接线。

当前接入决定：记录页的搜索改为筛选栏右侧图标，按需展开；工具双卡约80px高，历史纸卡保留核心卷身份、成绩或进度。实际答案订正使用成绩卡标签旁的短状态，点击进入详情；示例估分仅作静态标记。答题卡在公共BottomSheet内容就绪后挂载，列表独立滚动，选择后关闭并定位原答卷。

全局滚动条沿用纸卡暖灰，Chromium中可见宽度3px、轨道两端留空；抽屉把手仅缩小视觉标记。beUI输入框保留自有图标留位，通用表单样式仅适配原生字段，搜索框右侧交互式清空按钮单独留出52px。

本轮批注：选岗用途只在标题表达；首层始终提供国考／省考选择，来源按真实目录呈现，无省考时提供空态。判断推理四类在全局显示和排名中汇总，保持原题权重和历史答案。滚动条同时验证实际绘制尺寸与原生交互，不能只用伪元素computed style判定变细。


## 成长分析与计分口径

沿用当前 paper-cards-1114-v3 的暖纸卡、Fraunces 数字和小图标。分析首屏只显示题型、指标、核心数值和练习记录；一次练习用进度环，多次练习用真实时间曲线。记录每行只保留机构图标、卷名、日期、次数和对齐数值，完整身份保留在可访问名称中。所选曲线点只显示日期、次数和数值，避免与下方表重复卷名。

筛选面板使用三行图标纸卡：日期、来源、计分口径。七项题型直接点选，来源长列表才显示 beUI 搜索框。搜索字段保留独立外框和图标留位，覆盖原型全局原生 input 样式。日期由 React DayPicker 10.0.2 管理月份、日期运算、焦点和键盘，按钮复用 beUI，使用纸色圆角日期格，展示开始和结束日期并保留非法范围的就地反馈。

计分口径由完整逐题权重、折算和舍入规则确定，继续保证不同机构相同口径可比。选项以实际来源和卷型、题量、满分区分，按需展开板块、题数、满分表。帮助说明区分套卷分值和官方考试类别，不铺陈逐题序列或内部编号。

官方依据见 [计分口径核对](scoring-reference.md)。实现与验证范围继续记录在既有 ios-feature-integration 任务。
