Mobile UI Proposal · v0.1

一眼看到题，
一下点到答案。

小程序不是把网页缩小，而是把一次操作压缩到一个拇指能到的地方。所有页面遵守：一屏一任务、一卡一结论、一按钮一动作。

01

四条密度原则

先定“删什么”，再定“加什么”。移动端每一屏只保留一个主动作，其余降级为图标或收起。

一屏一任务

选卷页只负责找卷；答题页只负责选答案。说明文字移入“规则”抽屉。

每屏主动作 ≤ 1

数字先于文字

分数、题号、百分比用大号等宽数字。状态用色块 + 符号双编码，不靠长句解释。

1 个数字 = 1 条结论

拇指热区

高频动作固定在屏幕下半部：选项、上一题/下一题、提交与生成海报。

底部 1/3 承载主动作

渐进披露

先给结论，再给细节。题型默认只看最弱的 4 项，逐题统计点击“详细”才展开。

首屏信息 ≤ 3 组

05

密度改造：删了什么

同一份产品信息，移动端不是等比缩小，而是重新决定谁先出现、谁被折叠、谁只留一个图标。

旧版 H5信息平铺

  • 首页顶部同时出现标题、说明、题数、满分、版本、规则入口
  • 答题页四周都是信息：题型、分值、进度、说明、键盘提示
  • 报告首屏一次性铺满 6–9 个题型卡片，每个都带三行说明
  • 排行榜每行带头像、日期、题型明细、击败比例
  • 所有状态都靠文字解释“已选 / 已答 / 未答”

新一屏一结论

  • 首页只留续答、机构、期数、套卷四组；规则收进套卷详情
  • 答题页中间只留题号与 2×2 选项；答题卡从底部拉起
  • 报告先给分数、排名、最弱 3 项；完整题型进入“全部”
  • 榜单行只留名次、昵称、分数；时间放进小字
  • 状态用色块 + ✓ / × / · 双编码，零文字也能读
06

三项已确认的结构决策

以下三项已确认，直接作为组件结构与交互验收依据。

01
首页：续答优先

打开即回到上次进度；续答卡置顶，套卷列表紧随其后，不再用大标题与说明占首屏。

已确认 · 续答优先
02
报告首屏：最弱 3 项

按得分率从低到高只展示最需要行动的 3 项，其余进入“全部 6 项 ›”，避免首屏变成小字表格。

已确认 · 最弱 3 项
03
答题页：隐藏底部导航

答题时全屏沉浸，只保留返回与答题卡入口；退出答题后再回到首页三栏导航，减少误触。

已确认 · 答题页隐藏 Tab
