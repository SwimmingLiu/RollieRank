# 纠错模块验收证据

| 行为 | 证据 |
| --- | --- |
| 单题和多题反馈绑定答卷、版本、建议答案及依据，重启后保留 | corrections-service.test.js 的持久化用例；corrections-api.test.js 的重启用例 |
| 待审反馈与试算不改变正式答案或成绩 | 服务持久化与试算用例；浏览器试算前后正式成绩断言 |
| 未配置凭证或凭证错误时服务端拒绝审核 | 服务授权用例；HTTP 403 断言；浏览器错误凭证检查 |
| 维护者凭证不回显、不落盘，退出或刷新后清除 | 服务和 HTTP 响应及 catalog.json 断言；浏览器 DOM、localStorage、sessionStorage 断言 |
| 可按题号分批通过或拒绝，反馈者查看理由和状态 | 服务部分处理用例；浏览器先通过一题再拒绝另一题 |
| 批准后按 gradeVersion 重算全部同版本答卷，保持参考卷折算 | 服务批量批准用例，逐份比较 gradeVersion 的实际输出 |
| 答案、提交时间与参与信息保留，记录修订号及分数前后变化 | 服务批量批准用例；真实 HTTP 同步与本地恢复用例 |
| 正式总分不变时也更新答案对照并通知 | 服务 unchanged totals 用例 |
| 重复审核可幂等重试，已处理题目和旧答案依据被拒绝 | 服务重复、并发及过期依据用例；HTTP 重启后重试 |
| 无关题号的订正不会阻止继续审核剩余题目 | 服务并发用例在修订号更新后批准第二题 |
| 落盘失败回滚答案、成绩、审核、审计与反馈状态 | 服务故障注入；HTTP 用目录阻止 catalog.tmp 写入后逐项验证 |
| 未来提交使用新答案，旧客户端刷新后保留本地认领和参与选择 | HTTP submit、attempts/sync、syncAttemptSnapshots、loadState 用例 |
| 反馈者与其他受影响考生均可查看通知 | 服务通知隔离断言；浏览器双考生场景 |
| 同步失败可恢复，重试不会重复审核 | 浏览器中断 attempts/sync 后重试，核对审核记录仍为一条 |
| 键盘、弹窗切换、取消返回入口及窄屏可用 | 浏览器实际按键、焦点断言、四种宽度溢出检查及截图 |
| 报告、排行榜、分析和备份恢复读取订正后的快照 | 公共构建产物的 verify-features.py 完整旅程报告 |

模块浏览器报告为 test-results/corrections/verification.json，公共旅程报告为 test-results/corrections-integrated/results.json。两者使用临时数据目录及独立端口。界面记录只认证本任务的三个模块区域，公共应用整体交付由协调任务汇总。

默认 npm test 中的纠错浏览器用例需显式启用；本次已单独执行。其他任务的六项岗位 Excel 检查依赖单独的 Python 环境，不包含在本模块完成结论中。

固定源码哈希见 corrections-source-lock.json。最新公共扩充脚本的海报 depth 选择器超时和共享目录指纹变动交由协调任务复核，详情见 integration-corrections.md 的“模块锁定与公共复核”。这些记录不改变本模块专项检查的结论，也不用于声称当前全站已通过验收。
