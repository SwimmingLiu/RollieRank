# 将文本反馈改为可审核的答案订正链路

结果页原先只下载反馈文件，考生提交的问题无法在系统内处理。新增纠错模块保存逐题建议答案和核对依据，显示待审、部分处理、通过与拒绝状态，并提供“若建议答案成立”的个人成绩试算。

维护者需提供部署配置的 ROLLIERANK_REVIEW_TOKEN，服务端验证后才可按题号批量审核。批准操作在一次目录事务内订正相应版本标准答案、调用 gradeVersion 重算所有同版本答卷，并保存理由、修订号、前后成绩和审计；原答卷与提交时间保留。反馈者及其他受影响考生都能查看处理结果，后续提交使用新标准答案。

审核编号支持幂等重试。已处理题目、过期答案依据和并发修订会被拒绝；写盘失败会回滚答案、成绩及审计。凭证只留在浏览器会话内存，服务端不持久化或回显凭证，未配置时拒绝审核。

## 文件与接入

server/corrections.mjs 导出 createCorrectionsService；src/features/corrections.js 导出 createCorrectionsFeature；样式位于 src/features/corrections.css。结果页、个人记录页和管理页通过约定挂载点接入。精确接口、存储字段和公共同步要求见 [接入说明](integration-corrections.md)。

## 验证

服务测试与真实 HTTP API 测试覆盖持久化、未授权拒绝、通过和拒绝、多题重算、参考卷折算、重复审核、并发冲突、过期依据、未来提交、重启、旧客户端同步、原答卷保留，以及实际落盘失败后的回滚与重试。正式总分未变化的答卷也会更新答案对照并收到通知。

隔离 Chromium 流程验证多题表单、输入恢复、试算、凭证、审核确认、分批处理、双方通知、键盘操作及 320/390/1280/1440px 页面。它也模拟审核成功后的同步失败，确认两个刷新操作都会执行，重试同步不重复审核。截图和执行报告保存在 test-results/corrections，界面验收记录位于 .beauye/tasks/corrections。所有服务数据和端口均隔离。

公共构建产物的完整旅程脚本已通过 12 组检查，包含纠错对报告、榜单、分析及后续提交的影响，报告位于 test-results/corrections-integrated/results.json。四项功能的最终验收汇总由协调任务维护。此草稿只描述本地实现；没有创建远端 Issue 或 PR。
