# 纠错入口与订正状态

原纠错工厂公开 openFeedback(questionNumber?)，验证当前真实答卷与题号后打开现有 BottomSheet 表单。每次进入从新反馈开始；表单内继续支持增加题目、填写建议答案和依据、失败重试及提交后试算。取消和关闭只结束输入，不发送请求，不修改正式答案、成绩或原答卷。

iOS 包装提供 reportStatusView()，只读取同一份答卷的服务端订正通知。有真实答案变化时返回一枚可点状态；没有订正、仅有待审反馈或当前为样例时返回空字符串。状态只显示“答案已订正”和实际分数变化，题号、理由与版本在处理详情中查看。

报告不再显示常驻反馈卡，旧 corrections-report 挂载点即使仍在页面中也会清空。公共入口可把 reportStatusView() 放入 corrections-status 挂载点。逐题对照标题栏由协调任务调用 openFeedback，可传入选定题号。

个人记录没有反馈或通知时只呈现维护者审核入口；有内容或读取错误时保留原通知区域。审核页、凭证验证与原子重算均使用现有实现。

专项验证在独立 /ios-v3/ iframe 和真实 beUI BottomSheet 中进行，覆盖预填、多题、取消、试算、真实订正状态、详情、样例保护、授权审核及手机布局。公共 app.js、bridge、vendor 与用户端口的组合接入由协调任务完成。
